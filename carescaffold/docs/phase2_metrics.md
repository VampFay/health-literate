### Deviation 2 — LLM provider swap (operator-directed, v2.5)

Spec v2 §2 called for Anthropic Claude (Sonnet 5 for generation, Haiku
4.5 for fallback + safety judge) and Voyage AI `voyage-4-large`
embeddings. Operator directed a swap to **GLM-4-Plus via
`z-ai-web-dev-sdk`** for the LLM roles to remove the API-key blocker.

**What changed:**
- `config/model_registry.yaml` — `generation.primary` and `safety_judge.primary` both → `glm-4-plus`
- `llm/router.py` — Anthropic SDK replaced with `z-ai chat` CLI subprocess bridge
- Safety judge: Anthropic tool-use structured output → prompt engineering + first-label parsing

**Trade-off (spec §4.4.2 already acknowledged this):**
> "Use Claude's tool-use / structured output capability for the judge call
> to force one of the four fixed labels — do not parse free text for this,
> since Claude (unlike GLM-5.3) does support structured output reliably
> and you should use it here."

Spec anticipated GLM's lack of structured output. The v2.5 swap accepts
this trade-off:
- **Prompt engineering** constrains the model to reply with exactly one of
  {SAFE, BLOCK_DIAGNOSIS, BLOCK_DOSAGE, BLOCK_DIRECTIVE}
- **First-label parsing** extracts the verdict from the response
- **Fail-safe default:** any unparseable response or judge error → BLOCK_DIRECTIVE
  (never release an unverifiable response to the patient)

**Production swap path:** revert `model_registry.yaml` to Anthropic + Voyage,
set `ANTHROPIC_API_KEY` + `VOYAGEAI_API_KEY` in `.env`, swap `llm/router.py`
back to the Anthropic SDK with tool-use structured output.

### Deviation 3 — Held-out corpus generator (per Deviation 2)

Spec §4.4.3 said: "prompt Claude Sonnet 5 directly, in a separate session
with no visibility into your rules or tuning corpus." Per Deviation 2, the
held-out corpus was generated by **GLM-4-Plus in a separate session** with
the same no-visibility guarantee. Same methodology, different model.

**Methodology:**
1. `scripts/generate_heldout_corpus.py` calls GLM with a generation prompt
   that gives the model NO visibility into:
   - Layer 1 regex patterns
   - The 34 tuning corpus cases
   - The 4 verdict labels
   - Anything about how the system classifies responses
2. The model outputs 12 novel patient prompts that attempt to indirectly
   extract forbidden content.
3. `scripts/generate_heldout_bad_responses.py` calls GLM again with the 12
   prompts and asks it to write a "what an unconstrained chatbot might say
   in response" for each. This preserves the no-visibility property: the
   bad-response generator sees only the prompts (which it generated), not
   any Layer 1 rules.
